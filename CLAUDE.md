# Wiki-Agentic — Agent Operating Manual

> Read this file completely before any operation. It is the root contract for how this system works.

---

## What This System Is

A bilingual (Vietnamese/English) macroeconomic research operating system.
You maintain the wiki, run research sessions, and produce audited reports.
The retrieval system is fully local: BGE-M3 + FAISS + SQLite. No external API for retrieval.

**Domains covered:** Monetary policy · Fiscal policy · Basel / capital regulation · Financial markets · Macro outlook

## The Four Operating Stages

### Stage 1 — INGEST: Source → Wiki

**When to use:** User has dropped a new file into `02_sources/` or `02_sources/Inbox/`.

**Commands:**
```bash
# Ingest a single file
python 07_scripts/librarian.py ingest 02_sources/{path/to/file.md}

# Sweep and ingest all files in Inbox
python 07_scripts/librarian.py sweep

# Always run after ingest
python 07_scripts/librarian.py sync
```

**What you do after ingest:**
1. Review generated nodes in `03_wiki/` — check that `type` and `domain` are correct
2. Set `confidence` honestly: start at 1 (auto), raise only after reading the source passage
3. Verify `source_refs` paths point to real files in `02_sources/`
4. Mark any LLM-generated sentence with `[LLM]` — do not hide synthetic content
5. Create contradiction nodes for any conflicts detected with existing wiki nodes
6. Run `librarian.py sync` — always, after any wiki change

---

### Stage 2 — RESEARCH: Topic Investigation

**When to use:** User wants to research a specific topic.

**Setup:**
```bash
# Create research workspace
mkdir "04_research/{topic_slug}"
cp -r "04_research/_template/." "04_research/{topic_slug}/"
# Fill in RESEARCH.yaml: topic_slug, title, primary_question, sub_questions
```

**Research flow:**
```bash
# Step 1: Run coverage probe on primary question
python 07_scripts/librarian.py synth "{primary_question}"

# Record probe results in RESEARCH.yaml coverage_probe section

# Step 2: Search based on probe state
# INGESTED → wiki is the foundation
python 07_scripts/librarian.py search "{sub_question}"

# PENDING → raw sources are main evidence
python 07_scripts/librarian.py synth "{sub_question}"

# TRUE_GAP → STOP. Log to gaps[]. Do not search further.
# Suggest 2-3 sources the user could acquire.
```

**Findings:**
- Write each distinct finding to `04_research/{topic}/findings/{concept}.md`
- Use finding frontmatter (see 01_schema/frontmatter.md for format)
- Flag TEMPLATE_INSIGHT if you notice a pattern worth capturing in a template
- Do NOT promote findings to wiki until the promotion gate is satisfied (see §Decision Logic)

---

### Stage 3 — ANALYSIS: Draft from Wiki + Fresh Data

**When to use:** User requests analysis or draft based on completed research.

**Flow:**
```bash
# Load RESEARCH.yaml for the topic
# Load domain template: 06_templates/domains/{domain}/{template}.yaml
# Load style template: 06_templates/styles/{style}.yaml (or T_MODE_DEEP for deep analysis)

# Run agentic search across all sub_questions
python 07_scripts/librarian.py agentic "{primary_question}"

# Fetch fresh data if topic is time-sensitive (saves to 04_research/{topic}/data/)
# → Use WebFetch tool for current rates, CB decisions, market data
```

**Before presenting draft to user — run audit checklist:**
```bash
python 07_scripts/librarian.py audit 04_research/{topic}/drafts/{draft}.md
```

The audit checklist (`06_templates/core/audit_checklist.yaml`) runs 10 checks across 5 categories.
Mark each pass/fail. Present only the fail items to the user for review.

---

### Stage 4 — REPORT: After Audit Approval

**When to use:** User has approved the audit. Time to write the final report.

**Flow:**
```bash
# Apply style template to draft → write final report
# Save to: 05_reports/{YYYY-MM}/{slug}.md

# Update report registry
# 05_reports/_index.yaml → add entry

# Re-check promotion gate for all research findings
# Run sync
python 07_scripts/librarian.py sync

# Log in wiki log
# Append to 03_wiki/log.md
```

## Commands Reference

### Search (read-only, no wiki changes, no sync needed)
```bash
python 07_scripts/librarian.py search "query"      # 4-phase KG²RAG pipeline
python 07_scripts/librarian.py synth "query"       # Coverage-aware (probe first)
python 07_scripts/librarian.py agentic "query"     # Multi-round 5-lens search
python 07_scripts/librarian.py deep "topic"        # Thin-node detection
```

### Knowledge (modifies wiki — always run sync after)
```bash
python 07_scripts/librarian.py ingest 02_sources/path/to/file.md
python 07_scripts/librarian.py sweep               # Ingest all Inbox files
python 07_scripts/librarian.py sync                # Rebuild all indexes
python 07_scripts/librarian.py lint                # Wiki health check
python 07_scripts/librarian.py status              # Index + daemon status
```

### Research session
```bash
python 07_scripts/librarian.py session-close {topic_slug}   # End session + TEMPLATE_INSIGHT summary

python 07_scripts/librarian.py template-reject {insight_id} --reason "..."
python 07_scripts/librarian.py template-apply --priority high
```

### Daemon
```bash
python 07_scripts/librarian.py daemon start
python 07_scripts/librarian.py daemon stop
python 07_scripts/librarian.py daemon status
```

## Hard Rules — Never Break These

1. **NEVER modify any file in `02_sources/`**. They are immutable raw inputs. Only `_source_registry.yaml` is writable.
2. **Every wiki node MUST have at least one `source_ref`** pointing to a file in `02_sources/`. No source = no node.
3. **Set `confidence: 1` on any node you create without reading the source.** Raise only after reading a specific passage.
4. **Mark every LLM-generated sentence with `[LLM]`.** Do not hide synthetic content. Users must know what is sourced vs synthesized.
5. **Run `librarian.py sync` after ANY wiki change.** The FAISS + SQLite indexes must stay current.
6. **When two sources disagree, create a contradiction node.** Do not silently pick one side. Contradiction nodes live in `03_wiki/contradictions/`.
7. **Do not promote time-sensitive facts to the wiki.** Current rates, prices, policy decisions → stay in `04_research/{topic}/data/`. Only structural/mechanistic knowledge gets promoted.
8. **Do not write a final report without an approved `audit_log.json` entry.** `"final_approved": true` must be set before writing to `05_reports/`.
9. **Vietnamese queries need no translation** — BGE-M3 handles VI natively. Use `vi_en.py` augmentation only for FTS5 exact matching.

## Decision Logic

### Wiki node vs research finding?

```
IF the claim is:
  - Structural / mechanistic (how a system works)
  - Supported by confidence >= 3 source
  - Reusable across multiple research topics
→ Create or update a 03_wiki/ node

IF the claim is:
  - Current events, specific dates/rates/prices
  - Uncertain or low-confidence (< 3)
  - Relevant only to the current research topic
→ Keep as 04_research/{topic}/findings/ only
```

### How to set confidence?

```
5: Multiple authoritative textbooks agree. Core established theory.
4: Single primary textbook OR multiple institutional papers (IMF/BIS/Fed).
3: Reliable secondary source — credible but not textbook-level.
2: LLM synthesis backed by at least one source partially supporting it.
1: LLM stub. No source verification. Mark everything [LLM].
```

### What to do with a TRUE_GAP?

```
1. Log to RESEARCH.yaml gaps[] with type: TRUE_GAP
2. Append to .cache/gap_queue.jsonl
3. Add to limitations section of any draft that touches this topic
4. Suggest 2-3 sources the user could acquire (by domain):
   Monetary: BIS WP, Fed staff notes, ECB WP, NBER working papers
   Basel: BCBS consultative papers, BIS Quarterly Review, FSB reports
   Markets: ISDA reports, SIFMA, Federal Reserve FEDS notes
5. Do NOT fabricate an answer for TRUE_GAP topics
```

### When to rebuild indexes (run sync)?

```
ALWAYS run sync after:
  ✓ Creating any new wiki node
  ✓ Updating body or thesis of any wiki node
  ✓ Deleting any wiki node
  ✓ Adding or moving a source file in 02_sources/

DO NOT run sync during:
  ✗ Search-only sessions (no changes made)
  ✗ Reading/reviewing wiki nodes
  ✗ Writing research findings (findings are NOT indexed — only wiki nodes are)
```

### Which analysis mode to use?

```
Standard research_memo / policy_note → for: overview, literature review, policy assessment
T_MODE_DEEP                         → for: mechanism analysis, plumbing/Treasury desk analysis,
                                           any topic with ≥ 3 sub-questions touching Plumbing or Treasury layers

T_MODE_DEEP selected automatically when:
  - User says "phân tích sâu" / "deep analysis" / "cơ chế" / "Treasury desk"
  - Topic involves T-account tracing across multiple entities
  - Topic involves FX intervention, repo mechanics, or CB operational framework
```

## Bilingual Operation Rules

BGE-M3 supports 100+ languages natively. Vietnamese works without preprocessing.

**Dense + sparse search:** No preprocessing needed for VI queries.

**FTS5 exact matching:** Run `vi_en.vi_augment(query)` before FTS5 queries. This appends EN equivalents from `01_schema/vi_en_dictionary.yml`. Example: `"lãi suất"` → `"lãi suất interest rate policy rate"`.

**Wiki node aliases:** Always include Vietnamese aliases in `aliases:` field.
```yaml
aliases:
  - QE
  - LSAP
  - nới lỏng định lượng        ← Vietnamese alias
  - mua tài sản quy mô lớn    ← Another form
```

**Research can be in Vietnamese:** RESEARCH.yaml uses English for consistency. Wiki node body can be English or bilingual. Reports follow the style template language convention (ask user if unclear).

## T_MODE_DEEP Protocol References

When using T_MODE_DEEP analysis mode, apply these protocol rules:

- **P1_awareness:** Use temporal tags (CURRENT 🟢 / LEGACY 🟡 / DEPRECATED 🔴) in TOP-DOWN ENTRY
- **P2_epistemic:** All specific numbers (%, bps, $, dates) must carry source labels: `[WEB-YYYY-MM-DD]` / `[RAW-BOOK p.X]` / `[LLM-E]`
- **P3_mechanistic:** All causal claims follow A → B → C structure with conditions stated explicitly. Never "usually..." without conditions.
- **P4_output:** One diagram only; `---` separator only 3 times; no ALL CAPS in body; no gaming/combat metaphors (Rule 11)

Rule 11 — Linguistic Sobriety:
```
❌ "Double Kill"       → ✅ describe the mechanism
❌ "Macro trap"        → ✅ "policy constraint: [specific condition]"
❌ "MOF wins"          → ✅ "intervention achieves [specific outcome]"
```

## Template Update Protocol

When you notice a pattern during research that would improve a template:

1. Add a `template_insights:` block to the relevant finding file
2. `session-close` command generates a TEMPLATE_INSIGHT summary at session end
3. User reviews and approves with `template-apply` or `template-reject`
4. Approved insights bump the template version and append to `_changelog.md`

**Rules for flagging insights:**
- Pattern must appear ≥ 2 times in the session (not a one-off)
- Must be general enough to apply across multiple topics
- For T_MODE_DEEP: only accept insights that preserve the 5-lens structure and Format Discipline

```bash
python 07_scripts/librarian.py deep "monetary_policy"   # Deep dive: what needs ingesting?
```
